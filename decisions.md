# Decisions log — testing layer for the auth-calcification-audit skill

Running record of design decisions, with rationale. Started 2026-07-07. This is raw
material for part 4 of the article series ("how do you test software whose output is
generated by an LLM?"). One entry per decision; newest at the bottom. If a decision is
reversed, don't delete it — add a new entry that points back.

---

## D1 — JSON-first generation, three artifacts (2026-07-07)

The skill emits a canonical structured JSON **first**, then renders the report and the
summary **from it**; the renderer never re-reads the audited codebase. The JSON ships as
a user-visible third artifact (`auth-calcification-audit.json`).

**Why:** (a) commit-then-render — forcing statuses/anchors into a strict format before
prose attacks the "confident narrative papering over unverified facts" failure class
(the live localStorage bug); (b) star topology — report and summary both render from one
source, so report↔summary consistency becomes a corollary instead of a separate
discipline; (c) tests get a machine side to assert on; (d) the JSON is a real product
feature (diff audits over time, CI gates in the audited repo).

## D2 — The rung framing: instruction < verified property < structural guarantee (2026-07-07)

"Markdown derived from JSON" inside one session is an *instruction*, not a mechanism —
the render step has ambient access to the whole analysis context, so markdown can drift
from JSON. We are deliberately at rung 2: JSON-first + a **cross-format agreement check**
that gives JSON assertions jurisdiction over the markdown. Rung 3 (fresh-context render
that sees ONLY the JSON) is deferred, not rejected — note the handoff's "~2× cost" for
two-pass is overstated (the render pass doesn't redo Phase 1 analysis).

## D3 — Claims-not-document scoping (2026-07-07)

Output has three registers: **claims** (findings, anchors, statuses, coverage, ranking —
canonical in JSON), **explanation** (why it matters, transitions — markdown-only, free to
vary, never asserted), **synthesis** (headline, posture — written in markdown, *recorded*
in JSON with the finding ids it draws on). Agreement contract: markdown may say **more**
than the JSON, never **different**.

**Why:** forcing all prose into JSON strings degrades the primary artifacts; the summary's
value is synthesis, which is not a field rendering.

## D4 — The fresh-eyes completeness test (2026-07-07)

Every schema field decision resolves by asking: *could a renderer holding only this JSON +
the two templates + the methodology write the full report?* If a template section can't be
filled from the JSON, the schema is missing a field. (This is also what makes an eventual
rung-3 render pass possible with zero schema changes.)

## D5 — Normalization rules (2026-07-07)

Every fact appears exactly once: counts are computed from arrays, never stored; backlog
rank is array order, no rank field; "split" verdicts are derived by comparing per-vendor
entries, never stored; findings live in ONE flat array with ids, referenced by boundary/
axes/backlog/headline. **Why:** anything stated twice can self-disagree — that would
rebuild the drift problem inside the single source of truth. Exception, deliberate:
likelihood is stored twice (raw human answer in `interview.answers`, normalized enum on
the axis) because they are different facts — what the human said vs. what the skill
concluded — and pinning both makes the mapping itself assertable (non-negotiable #1).

## D6 — Presence/absence discriminated union (2026-07-07)

Every finding is a `presence` claim (carries `evidence[]` anchors with **verbatim
quotes** — mechanically verifiable by re-reading file:line, zero LLM calls) or an
`absence` claim (carries `checked_patterns` — its search record; harness asserts it
covers every alternative pattern the profile lists). **Why:** presence claims can be
verified by grep; absence claims can only be audited by their search record. The live
storage bug was a wrong absence claim; the checked_patterns invariant is the mechanical
version of the playbook's "negative findings demand a second look."

**Validated immediately (2026-07-07):** hand-translating the committed mixed-edge-cases
report into the schema revealed that roughly half its `file:line` anchors are off by 1–4
lines (e.g. `setKeyValueStorage` cited at :24, actually at :22; `getLegacyUser` cited at
:17, actually at :21). The eyeballed baseline had broken anchors nobody noticed. The
evidence-quote invariant catches every one of these mechanically.

## D7 — Escape hatches: `other` vs `undetermined` (2026-07-07)

Two hatches with different scopes. `other` = "pattern determined and understood, just not
in the current vocabulary" — empirical taxonomies only (storage/refresh/idp
classifications, claims_handling, api_token_type); requires a note AND ≥1 cited presence
finding (you saw something concrete). `undetermined` = "could not determine" — any
detected verdict including boundary signal status; requires a note AND a paired
`coverage.gaps` entry. **Why:** without hatches, a closed enum forces the model to round
novel reality to the nearest value — a structured lie. `other` wires into the findings
system, `undetermined` into the coverage system; no new evidence machinery needed.
Logically exhaustive enums (presence/absence, low/moderate/high, mode) get no hatch.
Fixture assertions demand exact values — a hatch appearing on a fixture is a test
failure. The hatches deserve their own fixture eventually (out-of-vocabulary pattern →
must yield `other`, not get rounded); until then they're untested paths — known debt.

## D8 — Schema versions with the playbook, not with vendors (2026-07-07)

The schema sits at the detection-playbook's altitude: it owns the *categories*; profiles
own the *mapping* from vendor APIs to categories. Vendor identity is data (slugs, profile
filenames) — adding a vendor never changes the schema. Recurring `other` on an axis is
the signal the methodology is missing a category → evolve playbook + schema together as a
versioned change (`schema_version` bump, fixtures updated).

## D9 — Profile pattern manifest (decided 2026-07-07, not yet built)

The absence-claim invariant ("checked_patterns must cover the profile's alternative
patterns") requires the harness to read each profile's pattern list — prose won't do.
`vendor-profile-schema.md` gains a machine-readable per-concern pattern manifest (patterns
to check + which classification each maps to). Each profile becomes a data plugin for both
the skill AND the test harness.

## D10 — cost_evidence vs cost_confirmed (2026-07-07)

Cost is split: `cost_evidence` (the skill's mechanical qualitative read — level +
concrete basis, present in every run, never a duration) vs `cost_confirmed` (the
maintainer's own figure, only ever from an answers file; the skill never fills it).
**Why:** SKILL.md already makes this distinction implicitly ("the mechanical pass supplied
cost evidence"); the report template conflated them. Consequence: the Phase 3 restructure
must make the skill emit per-axis cost_evidence even in non-interactive runs — the
committed fixture reports don't do this today.

## D11 — Build order: cheapest feedback first (2026-07-07)

(1) schema file → (2) hand-written golden JSON via backwards-translation of
mixed-edge-cases → (3) SKILL.md Phase 3 restructure → (4) offline deterministic harness,
developed against the golden file + corrupted mutants of it (mutation-test the test
layer before any LLM call) → (5) headless-invocation spike, one fixture, tracer bullet →
(6) per-fixture assertion files → (7) cross-format agreement check. Deferred, named:
interview mocking, model matrix, LLM-as-judge for synthesis quality.

## D12 — Harness lives outside the plugin (2026-07-07)

Top-level `harness/` dir, own package.json and deps, never packaged with the plugin. The
plugin keeps shipping markdown + data only (the schema JSON is data, not code) — "reads
your code, never executes anything" is a trust property for an auth-adjacent tool, kept
deliberately, not by accident.

## D13 — Schema changes discovered by the backwards-translation (2026-07-07)

Hand-translating the mixed-edge-cases report forced three schema changes before any code
existed — the exercise doing exactly its job:
- **`evidence` is an array of anchors**, not flat file/line/quote — real findings cite
  multiple locations that jointly constitute the pattern (selector import + the call
  passing it; audience-less config + the bare token call).
- **`not_applicable` added to boundary signal status** — B4 in a no-SSR codebase is
  neither present/absent nor undetermined; it's a *determined* "concern doesn't arise,"
  ideally backed by an absence finding.
- **`vendors[].profile_verified` added** — the report metadata cites each profile's
  verification date; fresh-eyes rule says the renderer must find it in the JSON.

Also surfaced: the committed report's judgment-calls section doesn't cover all four axes
individually, though SKILL.md says all four interview questions route there in
non-interactive mode — the golden file follows SKILL.md (strict), making the golden file
stricter than the eyeballed baseline it was translated from.

## D14 — Known open questions (as of 2026-07-07)

- Per-vendor likelihood (mid-migration maintainers may answer per vendor) — deferred;
  changes the interview, not just the schema.
- Per-vendor cost_evidence — axis-level `basis` prose carries the split for now; revisit
  if it keeps being lossy.
- Interview mocking: skill affordance (`_interview.yaml`) vs harness-only scaffolding.
- Model matrix vs pinned model for CI.
- Where the agreement check draws the line on summary prose (scorecard is parseable;
  posture/headline matching needs the synthesis block).

## D15 — Harness stack: TypeScript, zero build step (2026-07-07)

Everything in `harness/` is TypeScript, executed directly by Node ≥ 23.6 native type
stripping (`node check_invariants.ts …`) — no tsx/ts-node, no compile step, currently
zero dependencies. A first Python prototype of the invariant checker was rewritten to TS
the same day (owner call: one language across the project). `mutants.ts` promotes the
mutation test of the checker from a one-off to a permanent artifact — `npm run mutants`
must show every mutant CAUGHT.

**Operational gotcha discovered:** Node on this machine comes via fnm, initialized in
`.zshrc` — invisible to non-interactive shells (agent sessions, CI, cron). Harness
invocations must not assume an interactive shell; use the stable path
`~/.local/share/fnm/aliases/default/bin/node` or ensure fnm is loaded. Directly relevant
to the step-5 headless runner. Caveat to carry: native type stripping does not
type-check — types in harness scripts are documentation until a `tsc --noEmit` step is
added (step 4).

## D16 — Phase 3 restructure shipped: JSON → two rendered views (2026-07-07)

SKILL.md Phase 3 now produces **three artifacts in order**: `auth-calcification-audit.json`
(the source of truth, conforming to `assets/audit-schema.json`, same suffix-increment
convention), then the report and the summary — each rendered **from the saved JSON alone**,
never from the codebase or from memory. The summary renders from the JSON, not from the
report (star topology, per D1). New **fork rule**: drift noticed mid-render is fixed in
the JSON first, then re-rendered — the views never fork from the model.

Supporting changes:
- **Phase 1** now records verbatim evidence quotes, complete absence search records, and
  per-axis cost_evidence (even non-interactive — per D10). Detection playbook updated to
  match (quotes, search records, "output of the pass" names the JSON).
- **Phase 2** records raw answers verbatim and normalizes likelihood via a **fixed
  documented mapping table** in SKILL.md — the table the harness asserts against (per the
  schema's likelihood invariant).
- **Templates became view-specs**: placeholders now name the JSON nodes they render from;
  report gains Skill version + link-to-JSON metadata lines; "Likelihood × cost" split into
  Cost evidence (always) / Likelihood (interview only); migration-readiness "~X%" replaced
  with the qualitative progress vocabulary; judgment-calls section states the
  all-four-axes rule; backlog states array-order-is-rank.
- **Version bump 1.2.0 → 1.3.0** (plugin.json + marketplace.json) — new output artifact
  is a feature-level change.
- Committed fixture outputs are now stale by design (they predate the JSON artifact and
  have known-wrong anchors, see D6) — they get regenerated during the step-5 headless
  spike rather than hand-fixed.

## D17 — Deterministic harness: two fail-fast layers, mutation-verified (2026-07-07)

`harness/` is now the real step-4 harness, structured as two validation layers behind one
CLI (`check.ts`):

- **Layer 1 — shape** (`lib/schema.ts`): ajv (draft 2020-12) validates against the
  skill's `assets/audit-schema.json`, read from the skill package directly — never
  copied, so the schema the tests enforce is byte-for-byte the schema that ships.
- **Layer 2 — relations** (`lib/invariants.ts`): I1–I8 — referential integrity, verbatim
  quotes re-checked against the audited codebase, non-negotiables as cross-field
  implications, escape-hatch pairing, duration sweep. Runs ONLY if layer 1 passed
  (fail-fast): invariant code assumes a well-formed document instead of
  defensive-coding every access.
- **Output contract** (parsed by mutants.ts and future CI): `SCHEMA …` = layer-1
  violation, `ERROR I<n> …` = layer-2, exit 0 ⇔ clean.
- **Type gate**: `tsc --noEmit` with `strict` + `erasableSyntaxOnly` — the compiler now
  enforces both correctness and the "runs on plain Node, no build step" constraint
  (types were documentation-only under bare type stripping, see D15). Shared document
  types live in `lib/types.ts`, mirroring the JSON Schema (schema wins on drift).
- **Mutation corpus doubled to 14, with layer attribution**: 7 shape mutants (bad enum,
  missing required, undeclared property = the stored-counts rule, silent `other`,
  absence-with-evidence = the discriminated union, evidence-less verdict, wrong
  schema_version) + 7 relational mutants. `mutants.ts` asserts each is caught **in its
  expected layer** — a wrong-layer catch fails the run, so the layering claim itself is
  tested. `npm test` = typecheck + golden check + mutants.
- First dependencies introduced (ajv, typescript, @types/node) — dev-only, harness-only,
  never shipped with the plugin (D12 intact).
- Dogfood catch: ajv strict mode flagged `minItems` without `type: "array"` in the
  schema's conditional else-branches — fixed in the shipped schema, so any consumer's
  strict validator stays quiet. The golden file passed its first formal shape validation.

Still missing from the harness (later steps): per-fixture expectation files (step 6),
the headless runner (step 5), cross-format agreement check (step 7).

## D18 — Headless invocation solved; tracer bullet landed (2026-07-08)

The handoff's biggest unresolved question ("how do you invoke the skill headlessly?")
is answered: **`claude -p` with `--plugin-dir <repo>/skill/auth-calcification-audit`** —
it loads the real plugin package (plugin.json + skills layout), so the test exercises
exactly what users install, not a copied approximation.

`harness/run_fixture.ts` is the runner: copies the fixture to a fresh workspace under
`harness/runs/<id>/` (committed fixtures untouched; old artifacts excluded so runs start
clean), spawns claude headless (non-interactive prompt, `--permission-mode
bypassPermissions` — acceptable in a throwaway copy of synthetic code; CI should narrow
this), harvests the three artifacts, validates the JSON through both harness layers with
quotes verified against the exact code the model audited. `runs/` is gitignored.

Supporting decision: **skill version now lives in SKILL.md frontmatter** (`version:
1.3.0`) because that's the only place the model can reliably read it at run time —
`meta.skill_version` sources from there; `lint_versions.ts` (in `npm test`) keeps
plugin.json / marketplace.json / SKILL.md in sync.

**First tracer-bullet run (calcified-cognito, default model = Opus 4.8): PASSED
end-to-end on the first attempt.** 488s, 33 turns, $2.75. All three artifacts produced;
shape valid; all invariants pass — including I4: every one of 11 findings' quotes
verifies verbatim against the fixture source. Recall eyeball: every designed trap hit
(leaky facade, AuthSession in app code, direct imports, vendor-mocked tests + no
contract suite, default localStorage, bare refresh, inline cognito:groups claims,
fetchUserAttributes spread, ID-token-for-API). The storage absence finding carries a
five-pattern search record spanning v5+v6 APIs and the look-alike selectors — the
original real-run localStorage bug is now structurally unrepeatable in silence.
Non-negotiables held: likelihood all null, backlog/interview/migration all null,
judgment calls cover all four axes, disclaimer correctly not fired for Opus 4.8.

Committed calcified-cognito outputs replaced with the verified run artifacts (per D16);
re-validated against the committed fixture path. The other three fixtures remain stale —
regenerating them is ~3 runs × ~$3 and belongs with step 6, where their expectation
files get written.

Cost/latency datapoint for CI planning: one fixture run ≈ 8 min, ≈ $2.75.

## D19 — Pinned test model + the free slice runs on every commit (2026-07-08)

**Default test model = Opus 4.7** (`claude-opus-4-7`), pinned in run_fixture.ts —
the skill's minimum verified tier, so live tests exercise the weakest model we
recommend rather than whatever the CLI defaults to (the D18 spike ran on Opus 4.8 by
accident of defaults). `--model` overrides for matrix runs. Partially resolves the
D14 "model matrix vs pinned" question: pinned default now, matrix later.

**Pre-commit hook via `core.hooksPath .githooks`** — husky's job without the
dependency: the hook script is committed at `.githooks/pre-commit`, and
`harness/package.json`'s `prepare` script sets `git config core.hooksPath .githooks`
on every `npm install`, so fresh clones self-install it. Escape hatch:
`git commit --no-verify`.

**What runs free at commit time** (the whole `npm test` chain — no LLM calls,
~2–3s, and only when `harness/`, `skill/`, `fixtures/`, or `.claude-plugin/` files
are staged; docs-only commits skip in ~10ms):
- `typecheck` — tsc strict over the harness (runs/ workspaces excluded — fixture
  code is not harness code).
- `lint` — the three-way version sync (plugin.json / marketplace.json / SKILL.md).
- `check` (new `check_all.ts`) — golden file + EVERY committed fixture audit JSON
  validated through both layers against their fixture source. The quiet killer
  feature: editing fixture source now breaks the commit if it invalidates committed
  anchors (I4), instead of silently rotting them — the committed-report bug class
  from D6, guarded at the door. Self-extending as fixtures gain JSON artifacts.
- `mutants` — all 14, layer-attributed, so a schema edit that silently loosens
  validation (or a checker regression) fails the commit that introduces it.

What never runs at commit time: `run_fixture.ts` (live LLM runs — money and minutes;
manual or CI-scheduled only).
